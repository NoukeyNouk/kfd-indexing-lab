# Ускорь индексацию

Подборка доступных товаров по рекомендациям с учётом исключений и повторений.

## Начало работы

[Полное задание](docs/TASK.md). Работа выполняется в собственной копии репозитория.

| Файл | Назначение |
| --- | --- |
| `src/main/kotlin/lab2/Product.kt` | Тип данных |
| `src/main/kotlin/lab2/ProductSelection.kt` | Реализация подборки товаров |
| `src/test/kotlin/lab2/ProductSelectionTest.kt` | Тесты обязательных сценариев |
| `README.md` | Инструкция запуска и ответы по работе |

```bash
./gradlew test
```

```powershell
.\gradlew.bat test
```

Ссылка на репозиторий отправляется в Academy.

## Основное задание

### Решение

Реализация: [ProductSelection.kt](src/main/kotlin/lab2/ProductSelection.kt).

Сначала исключения преобразуются в множество для быстрой проверки наличия id.
За один проход по каталогу доступные товары, которых нет в исключениях,
добавляются в изменяемую карту с ключом id и значением Product. Это позволяет искать
товары по идентификатору без полного просмотра каталога для каждой рекомендации.

Рекомендации просматриваются в исходном порядке. Операция `remove(id)` удаляет
товар из карты и возвращает его для добавления в результат; если товара нет,
рекомендация пропускается. Поэтому первое появление id
определяет позицию товара, а повторения не добавляют его снова. Недоступные и
исключённые товары не попадают в карту, неизвестные id пропускаются.
Товары, которых нет в рекомендациях, не добавляются.

В результат попадают полные исходные объекты Product. Все вспомогательные
коллекции создаются внутри вызова; входные списки не изменяются, а повторные
вызовы независимы. Если подходящих товаров нет, результат пустой.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях;
- `k` — число товаров в результате, `k ≤ min(p, r)`.

**Время выполнения: O(p + r + e)** в среднем при операциях поиска, добавления
и удаления в хеш-коллекциях за O(1), а также амортизированном добавлении в конец
списка за O(1). Построение множества исключений занимает O(e), проход каталога
с заполнением карты — O(p), проход рекомендаций — O(r).
Оценка предполагает обычную работу хеш-коллекций без большого числа коллизий.

**Дополнительная память без результата: O(p + e).** Множество исключений занимает
O(e), карта подходящих товаров — O(p).
Для результата отдельно требуется O(k) памяти: он хранит
ссылки на исходные товары, не копируя объекты и их имена.

### Тесты

Тесты находятся в [ProductSelectionTest.kt](src/test/kotlin/lab2/ProductSelectionTest.kt).
Два начальных теста сохранены. Ожидаемые результаты заданы явно и сравниваются
как полные списки Product.

| Что проверяется | Тесты |
| --- | --- |
| Обычная подборка; порядок рекомендаций отличается от порядка каталога | `selectsAvailableProductsInRecommendationOrder`, `preservesRecommendationOrderRegardlessOfCatalogOrder` |
| Повторяющиеся рекомендации и исключения | `handlesRepeatedRecommendationsAndExclusions` |
| Недоступные, исключённые и неизвестные товары | `skipsUnavailableExcludedAndUnknownProducts` |
| Пустой каталог, пустые рекомендации, пустые исключения | `returnsEmptyListWhenCatalogIsEmpty`, `returnsEmptyListWhenThereAreNoRecommendations`, `preservesRecommendationOrderRegardlessOfCatalogOrder` |
| Ни один товар не подходит | `returnsEmptyListWhenNoProductsQualify` |
| Входные данные не изменяются; повторные вызовы независимы | `doesNotModifyInputsAndKeepsRepeatedCallsIndependent` |
| Товары вне рекомендаций не включаются | `doesNotIncludeProductsMissingFromRecommendations` |
